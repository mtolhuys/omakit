## Effect on Omakit

setup-node verifies the selected Node executable against the tool-cache
version after adding it to PATH, and retries manifest acquisition three times
with one- and two-second delays. It adds mise.toml parsing and resolves absolute
version-file inputs correctly. Omakit requests explicit Node 22/24 versions,
uses no version file, and disables automatic package-manager caching. The
cache toolkit update, TOML parser and rebuilt bundles belong to the action;
they add no Omakit runtime dependency. Inputs, Node 24 action runtime and
authentication behavior used here retain their contracts.

download-artifact leaves `src/` and `action.yml` unchanged. Its artifact
toolkit advances from 6.2.1 to 6.3.1. The bundle honors positive integer
Retry-After seconds on HTTP 429, changes the base retry interval from three
to eight seconds, and caps cumulative retry waits at 120 seconds across
at most five attempts. Bundled dependency changes also include Azure storage
12.31.0, Octokit retry fixes, large-integer JSON handling and a sanitized
Actions orchestration identifier in the user agent. Download selection and
the digest-mismatch error default remain unchanged. Omakit's release and pin
proposal jobs still select named artifacts from their own run; token scopes,
digest checks, tag-only publishing and npm provenance remain enforced by the
existing structural tests.

This is an integration review of the exact published action changes, not a
claim to have independently audited every transitive dependency or exercised
GitHub's hosted artifact service locally. CI exercises setup-node on Node 22
and 24; the download action runs when the release or pin-proposal jobs need
their artifacts.

## Validation and release decision

Updating workflow SHAs alone reproduces the action-audit failure: nine of ten
workflow tests pass and the explicit audit test refuses the unapproved pins.
Updating the two reviewed allowlist entries restores all ten tests without
changing their assertions. `./bin/omakit pin` confirms the clean pinned
checkout, and `npm test` passes all 604 tests with no skips or failures.
The package assertion also passes.

Only workflows, their test, contributing guidance and this audit record
change. None is an npm package payload file. `npm pack --dry-run --json` and
`tests/package-assert.mjs` confirm 135 publishable files, 381,140 packed bytes
with the checkout's null source record, below the 409,600-byte ceiling. Of
those files, all 134 payload files compare byte-for-byte equal with npm's
published 0.6.12 archive; the remaining `tools/blocks/commit.json` is filled
by the release workflow with source commit
`3696bb6e67a3eba4dda9fea94a88afcd34fd2245`. Omakit still has zero runtime
dependencies. No new package version is needed: 0.6.12 already carries the
reviewed marketplace pin and submission handling.
