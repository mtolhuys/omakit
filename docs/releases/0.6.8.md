# 0.6.8

Tested plumbing, the marketplace's own checks, and a disposable Omarchy to test in.

`omakit inspect` now cites a copy to a variable destination under the
file and state boundary class. Theme Manager was blocked twice in one
review thread for `cp "$src" "$dest"` onto a destination the script is
handed (`install-wallpaper.sh`, 2026-09-11; `install-hook.sh`,
2026-09-22). A link planted at `$dest` sends the copy wherever it points.
At both blocked commits the class cited neither copy: the extraction gave
`$dest` as `unknown`, and the class admits only a path it can see is
outside a controlled directory. Measured on those trees, the
class now goes from 7 sites to 9 with `install-hook.sh:24` among them,
and from 4 to 6 with `install-wallpaper.sh:83`.

## A write to one variable

A write's `controlledDirectory` has a fourth value, `variable`, for a
canonical path that is one variable and nothing else (`$dest`, `$2`,
`$target/`) and not `$HOME` or an XDG name. Any other path the
classification cannot place, `$dir/name` included, stays `unknown`. The
class admits a `variable` row written by `cp`, `mv`, `install` or `ln` and
says it as what the text shows:

```text
2 writes by cp to a variable destination, not resolvable to a controlled directory
```

It says nothing about who set the variable, because the extraction
follows no assignment.

## Why these four verbs, and not a redirect

A link planted at the destination picks where the file lands for all
four, measured on GNU coreutils 9.11: `cp` writes through a link to a
file, and all four put the file inside a linked directory. A redirect and
`tee` write through a link too, and are left out for their count: over 15
plugin trees, 28 writes by the four verbs go to one variable, against 61
redirects and tees, 24 of them `>>` appends to a log. Across the 15 trees
the class's count goes from 96 to 124. The figures, their limits and what
stays uncited are in `docs/MEASUREMENTS.md` (M11), with a record.

## Also in `inspect`

- On a line with two writes (`printf ... > "$f.tmp" && mv "$f.tmp" "$f"`)
  the default view shows the write the class cited, not the first one.
- For `cp`, `mv`, `install` and `ln`, `-t` and `--target-directory` now
  read that directory as the destination; before, the last source was
  taken for it.

## For `--json` consumers

Code that switches on `observed.writes[].controlledDirectory` sees the new
value `variable`. The contract in `tools/inspect/contract.mjs` holds it to
a path of that shape, and `docs/INSPECT.md` describes it. The share the
class prints, and every other figure, are unchanged.

The pin is unchanged at `b7b29654`: nothing omakit reads has moved on the
marketplace since 0.6.7.

```bash
omakit upgrade
```
