# 0.6.10

Tested plumbing, the marketplace's own checks, and a disposable Omarchy to test in.

`omakit doctor` no longer calls the pin behind when the marketplace edits
a file omakit reads only for a value or two and leaves those values as
they were. On 2026-09-30 it graded the pin `advice` because
`scripts/build-catalog.mjs` had moved three times since `b7b29654`
(a166e3ac, b612419c, cb7947ec). omakit never runs that file; it reads the
reserved plugin-id namespace and the category mapping out of its text,
and neither changed. `build-catalog.mjs` is the most edited file under
`scripts/`, so comparing it by blob meant a release for nothing, again
and again.

## What is read out of a text-read file, compared

`PIN_READS` in `tools/marketplace/pin.mjs` now names, for each of the three
files omakit reads as text, the values it takes out of it, as functions
from text to value: `reservedNamespace` and `catalogPresentation` from
`build-catalog.mjs`, `validatedLabel` from `approve-submission.mjs`,
`updateLabel` from `approve-plugin-update.mjs`. The checks call these on
the pin's text; `doctor` calls the same functions on the pin's text and,
when the file's blob moved, on its text at HEAD, read once through the raw
file host at the exact commit, compared and dropped, never imported.

- `ok`: nothing omakit reads counts as moved. A text-read file that moved
  with every value unchanged is named: "scripts/build-catalog.mjs moved,
  and the 2 values omakit reads from it are unchanged".
- `info`: what counts is only files omakit takes wording or a label out
  of, as in 0.6.7.
- `advice`: a file omakit executes or reads a rule from moved, a value
  read out of a text-read file differs (both values are printed), a read
  file is gone at HEAD, or the form moved, as in 0.6.7.

In `--json`, `moved` keeps meaning the blob, and the evidence adds
`effective` (what the grade is taken from) and `textReads` (each text-read
file, whether its blob moved, and each value at the pin and at HEAD). No
existing line or field changed. The weekly pin-freshness workflow grades
on `effective` and names the text-read files that moved with their values
unchanged.

Measured on 2026-10-01 (`docs/MEASUREMENTS.md` M7), with the code each
release shipped run against the marketplace's own history: of the five
commits since `38060f89` that touched a file omakit reads, 0.6.6's tree
comparison and 0.6.7's blob comparison grade all five `advice`, and this
comparison two, the policy module change (40315f2) and the parser and
form change (7dd6e56).
