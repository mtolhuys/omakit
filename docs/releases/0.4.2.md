Review cost is reported before a submission is posted, and a bug hunt closed five defects where a result was cut, zeroed or misattributed.

- `submit` reports `review.cost` immediately after the baseline: automated, manual queue, or manual queue again with the account's open-issue count for the same repository and batching advice. It is always advisory, never blocks readiness or removes the body, and adds `reviewCost` to JSON.
- `watch --all` adds a review-cost summary: how many listed issues are plugin updates on the manual-review label, and how many of those have documentation-only diffs between validated commits, with compared and skipped denominators and a reason on every skipped row. A missing validation record is never replaced by a Git parent.
- M9 records a dated, complete open-update population measurement with a reproducible read-only command; M6 corrects the historical sample denominator and adds complete dated per-issue staleness reads with unknown comparisons kept explicit.
- Every command that has written its result leaves through the exit code, never `process.exit()`, so a pipe whose reader starts late receives the whole output. Before, `submit <listed plugin> --json | (sleep 2; cat)` delivered 8,192 of 14,033 bytes and the parser downstream saw invalid JSON.
- An option written as `--name=value` is read by every command that reads one, as the option table already accepted. Before, `doctor --out=FILE` wrote nothing and exited 0, and `submit --category=X --tags=Y` said both flags were missing.
- `submit` on a subject without a github.com origin waits on `submission.repository-url` instead of listing `submission.validation-commit` as a second blocking cause with "could not read the default-branch HEAD (unknown): ".
- `weigh` treats a shell pid that is not in `/proc` when the window opens, or gone when it closes, as a run with no sample instead of a completed run of zeros; and an interrupt whose restore did not verify is reported as the unverified restore with the backup kept, never as "shell.json was restored".
- `watch` no longer renders a bot account's comment as the discussion, counts it as a reviewer, or dates the last human review by it.
- The lab gate `tests/lab/weigh.sh` has two modes: `smoke`, the default, proving a real restart, real `/proc` reads, the restore and an interrupt's recovery in about a minute of measurement; and `evidence`, the five-run gate. Both preflight on the host in seconds before any guest boots, and the evidence gate fetches its three listed plugins read-only at the commits the pinned catalog records as validated instead of using whatever the desktop had installed.
- The README is shorter, with one recorded GIF per command, refreshed captures and dated evidence for every claim.

Each fix carries a regression test that failed before it. Issue bodies, JSON meanings, exit-code semantics and the marketplace pin are unchanged; no dependency or command was added.
