# 0.5.0

The `inspect` size score is a tree-level, line-weighted position among listed trees, so splitting a long function raises it; three extraction faults behind it are fixed and M12 is re-measured with a script that reproduces it; `--allow-dirty` says what it reads.

- The old score was 10 minus the mean rank of the tree's functions among
  the listed ones, each function's rank the largest of its three
  percentiles. Ten small functions weighed the same as one huge one, so
  every decomposition raised the mean and lowered the score. Measured on
  a listed plugin of 332 functions scoring 3.75: splitting a 12-function
  shell script into 35 single-purpose functions left it at 3.75, and
  splitting an 84-line, nesting-5 Python function into eight named steps
  lowered it to 3.72. The docs called it a position among listed
  plugins, but nothing compared the tree with listed trees.
- The new score is a position among listed trees: `heavyShare` is the
  share of the tree's function lines that sit in functions over any M12
  threshold, and the score is 10 minus the share of the 50 listed trees
  with a strictly smaller `heavyShare`, divided by 10. A tree with no
  function over the thresholds scores 10.00, a tree heavier than every
  listed tree 0.00, a tree with no function has no score. Splitting a
  long function moves its lines out of the heavy set and raises the
  score; adding small functions beside a long one barely moves it, which
  the unit tests hold. On the same plugin the two refactor commits now
  raise the score instead of lowering it. The report line reads
  `size score  7.40 of 10; 12% of its function lines sit in functions over
  the measured size, less than 74 of 100 listed trees (M12)`; `--json`
  carries `size.heavyShare` and the listed trees' shares under
  `size.sample.heavyShares`. The `long functions` block and its
  thresholds are unchanged in form.
- Three extraction faults are fixed, each with a fixture under
  `tests/fixtures/inspect/`. A Python body is depth 0 the way a shell or
  QML body is, with the indentation unit read from the first body line
  (`python-depth`); a brace that opens an object or array literal or an
  inline arrow body is not a nesting level (`literal-nesting`); a named
  arrow function (`const load = (rows) => {`, `this.load = rows => {`)
  and a method shorthand (`load(rows) {`) are functions, so a
  `*Model.js` is no longer invisible, while anonymous callbacks stay
  uncounted (`arrow-and-method`). The literal test is a
  regular-expression heuristic over the text before the brace, and says
  so.
- M12 is re-measured over the same 50 listed trees with
  `node tools/inspect/measure-functions.mjs`, which applies the record's
  selection rule, fetches each tree read-only at its validated commit and
  writes `docs/evidence/inspect/<date>-function-lengths.json` with the
  histograms, the quantiles and, per tree, the function count by kind,
  the longest and median length, the function lines, the heavy lines and
  the heavy share. 6041 functions; the nesting p90 moved from 3 to 2 with
  the fixes, lines and branches did not move. The 0.4.3 record is in the
  file's history and named in the new record's notes and in
  `docs/MEASUREMENTS.md`.
- `--allow-dirty` has always read HEAD from the object database, but the
  refusal said "check the tree as it is". It now says `commit them, or
  pass --allow-dirty to inspect HEAD as committed; uncommitted edits are
  not read`, and under `--allow-dirty` the report carries one line saying
  how many files differ from HEAD and were not inspected;
  `subject.uncommittedFiles` carries the count in `--json`.

Nothing in the issue bodies, the JSON meanings of the other commands, the exit-code semantics or the marketplace pin changed; no dependency was added; nothing is posted anywhere.
