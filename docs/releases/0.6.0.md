# 0.6.0

Tested plumbing, the marketplace's own checks, and a disposable Omarchy to test in.

Two blocks are files a plugin copies into its own tree with `omakit add`, and
`inspect` reads them. The README, package description and recordings now lead
through build, check, track and prove in that order. Every number below is in
the record it names; nothing here says a plugin passes review, and no reviewer
has seen a ported plugin yet.

## What the review blocks on: M13

## Run 0.2.1, `omakit add run`

`blocks/run/`: `Run.qml` and `run-supervisor.py`, started through
`/usr/bin/python3 -I -S -B`. One program by absolute path, argv only
(string-program forms refused, best effort over the list in
`docs/BLOCKS.md`, unless `allowShellString` is on its own line), a
closed environment (`PATH=/usr/bin`, `HOME`, `LANG`,
`XDG_RUNTIME_DIR`, plus what `environment` names), a hard deadline,
byte and line caps while reading, control characters stripped, TERM
then KILL to the whole group through a pidfd, the leader reaped last,
one result object with a state word: `ok`, `exit`, `timeout`,
`overflow`, `cancelled`, `spawn-failed`, `supervisor-lost`,
`python-missing`. Chosen by the spike (`docs/BLOCKS_SPIKE.md`): 36 runs,
five scenarios, two designs, both end every scenario, the supervisor
chosen for reaping last. 0.2.0 is the hardening round of 2026-09-18
(`docs/evidence/blocks/2026-09-18-review.json`): the protocol between
`Run.qml` and the supervisor carries a per-run token the program cannot
see, so a line the program writes into the pipe through `/proc` changes
nothing; a supervisor that dies leaves no group behind; a program forked
before `Run.qml` knew its pid waits behind a gate; a `start()` queued
behind the backstop follows in order; and the string-program refusal
covers the forms `docs/BLOCKS.md` lists. The lab suite `tests/lab/run/`
holds 19 scenarios, six of them new and each failing on 0.1.0: 19 of 19
on the desktop (`docs/evidence/blocks/2026-09-18-run-lab-desktop.json`)
and 19 of 19 on the stock 4.0.3 guest through `omakit lab prove run`, the
installed package `omarchy 4.0.3-1` read by the run and the session not
linked (`docs/evidence/lab/20260918-160936-run/runlab.json`).
Each contract line in `docs/BLOCKS.md` carries its M13 count. 0.2.1,
the release decision of 2026-09-18: `sudo` and `doas` leave the
supervisor's wrapper list, in the open, because the marketplace baseline
is a source scan and read the two words as a privilege request in every
plugin that carried the block. Run refuses no privileged wrapper and
decides nothing about privilege; the neutral wrappers and the
interpreters with their string flags stay refused. Measured before and
after on a plugin with nothing but the block
(`docs/evidence/blocks/2026-09-18-run-block-baseline.json`): 0.2.0
review-required with `privilege`, 0.2.1 passed with no capability. The
Run suite ran again on the stock guest at 0.2.1
(`docs/evidence/lab/20260918-172451-run/`, 19 of 19; a first run four
minutes earlier, `20260918-172116-run`, ended the `stubborn` scenario at
3,925 ms against a 3,500 ms gate and is kept as what it is, one timing
miss on a scenario 0.2.1 does not touch, since the change is two strings
in a frozenset), and `omakit add run --update` moves a
copy to it, its header included, on the Theme Manager `run-port` branch
at `762859d`.

## Store 0.2.0, `omakit add store`

`blocks/store/`: `Store.qml` and `store-helper.py`, taken from Theme
Manager's cache transaction. One private file per plugin under the XDG
state or cache base, reached from `HOME` by descriptor with
`O_NOFOLLOW|O_DIRECTORY` at every step, checked after every open and
never before (owner, regular file or directory, not group- or
other-writable), read under a cap and a JSON schema subset, written
through an exclusive 0600 staging file and a rename with fsync, stale
staging swept after 600 s. States `ok`, `missing`, `invalid`,
`refused`, `overflow`, `failed`, `helper-failed`. `store` brings `run`,
which it starts its helper through. The lab suite `tests/lab/store/`
plants 12 hostile conditions in a throwaway HOME (links at the
directory, the parent and the file, a swap under the read, an oversized
file, a group-writable and a foreign-owned file, an invalid document, a
crash between staging and rename, ten concurrent writers, a base outside
HOME, and from 0.2.0 a FIFO at the file's name, a write cut short by
`RLIMIT_FSIZE`, a non-ASCII file within the cap): 15 of 15 on the
desktop (`docs/evidence/blocks/2026-09-18-store-lab-desktop.json`) and
15 of 15 on the stock guest through `omakit lab prove store`, the foreign
owner simulated with `chown root` there
(`docs/evidence/lab/20260918-161230-store/storelab.json`). 0.2.0 opens the file without blocking and refuses a
FIFO by name, writes every byte or fails with nothing staged, carries
the value as UTF-8, counts the write cap in bytes and caps the schema,
closes the walk's descriptors on a refusal, and refuses a schema outside
the subset or a value nested past 64 levels without a traceback.
The helper is importable: `open_private_directory` and `result_of` take
the environment from the importer.

## Blocks as files

Six-line headers name the block, its version, the licence, the omakit
commit and the body's sha256; `blocks/history.json` is the append-only
record of every shipped body, and `omakit add <block> --update` moves an
unmodified copy to the current version and refuses a modified one.
`omakit add` is the one command that writes into a plugin tree, and it
writes only under `omakit/`. A `NOTICE` lists every block present.

## inspect reads the blocks

- An unmodified block is one `blocks` row and raises nothing at its
  lines; a modified copy is reported as modified and read like any other
  file.
- A `Run {` site is a process whose deadline the block holds
  (`deadline.via: "block-run"`); a `Store {` site is a write under the
  plugin's own directory at mode 0600 (`via: "block-store"`).
- A helper the QML starts through Run runs in the block's closed
  environment: its shell rows carry `closedEnvironment: true` and the
  environment-trust class counts their tool names apart. A helper is
  Run-started only when a site's `argv[0]` resolves to it through the
  text (literals, `+` chains, `Qt.resolvedUrl`, `Quickshell.env`,
  identifiers through the nearest assignment or binding, same-file
  functions through their return expressions); a path the text does not
  show resolves to nothing, and the row stays counted. Measured on Theme
  Manager: the superseded base-name rule read 481 to 298 with 183 names
  in 12 helpers; the resolved rule reads 484 to 434 with 50 names in 9
  helpers, 12 of 24 sites resolving.
- A line starting with `exec` is a process site; an argv word that is
  an expression is not a tool resolved from PATH.

## The lab: prove, `omakit lab`

The fourth job. The three gates that proved the blocks and `weigh` on a
stock 4.0.3 guest each carried their own driver, needed a sibling
checkout of `omarchy-plugin-lab` nothing documented, ran the guest
dev-linked to a source checkout while the evidence said "stock", and
verified an ISO found by scraping "latest" against a sidecar fetched
beside it (`docs/history/2026-09-18-lab-inventory.md`, twenty-two
problems). Now: one lab module under `tools/lab/`, one harness
(`tools/lab/harness.sh`) with the three suites as data and bash bodies,
and one command surface (`docs/LAB.md`):

- `omakit lab prove <suite>`: the Run block's 19 scenarios, the Store
  block's 15, `weigh` smoke and `weigh-evidence`, in a disposable guest
  booted from an immutable base through a fresh overlay; the guest's
  installed `omarchy` package and whether the session runs from it are
  read over SSH and printed before the suite, and written into the
  document with the run id (`where`, `lab`); the overlay is measured and
  removed and the base checked unchanged on every exit path. It boots
  nothing until the base, the host and the suite's files are there, and
  otherwise names each missing thing with what it takes and the one
  command; it fetches nothing.
- `omakit lab inspect`: read-only; the pinned release with its exact
  size in GB and GiB, digest and signer, what is on disk and whether it
  was verified, the toolchain, the host.
- `omakit lab setup`: the only path that fetches bytes, after one consent
  naming the exact size and destination (`--yes` for an agent), a
  resumable literal GET of the pinned URL or a copy of `--from <file>`,
  the byte count, the SHA-256, the sidecar and the detached signature
  against the packaged Omarchy key at the pinned fingerprint, failing
  closed; then one base built by the pinned omarchy-iso toolchain from a
  copy of its harness under the lab, booted once to read the installed
  package, hashed, made read-only, given a manifest, promoted with one
  rename. The toolchain is never fetched: the one command that prepares
  it is printed, and `--toolchain <dir>` records it after hashing its
  harness against the pin.
- `omakit lab prune`: what the lab owns with its bytes, asked once,
  refused while a QEMU answers, recovered bytes said.
- `omakit doctor`: the lab's lines, each with its measured reason,
  advisory.

Measured on 2026-09-18 (M14): the base built in 5m 57.8s; the Run suite
ran 19 of 19 on guest `omarchy 4.0.3-1`, skew false, in 2m 53.4s, with a
413,470,720 B overlay removed and the base unchanged
(`docs/evidence/lab/20260918-160936-run/`). `tests/unit/lab.test.mjs`
holds the argument lists a guest is started and reached with, proves the
download against a local origin and the verification against a
throwaway key, and reads every file under `tools/lab/` for a word that
would reach the host's session. `tests/unit/self-containment.test.mjs`
sniffs every file in the tree for an image or archive signature: no ISO,
image, base, firmware variables or overlay ships, ever.

## Limits

- No reviewer has seen a ported plugin. Both ports are branches; the
  submissions and their outcomes are still ahead, and the evaluation
  date in `docs/BLOCKS_PLAN.md` is 2026-10-15.
- M13's counts come from a classifier over review comments and are an
  upper bound on what a block can own; "raises" is not "resolves".
- The blocks need `/usr/bin/python3` on the machine; a stock Omarchy
  4.0.3 has it, and `Run.qml` reports `python-missing` otherwise.
- Run 0.2.1 refuses no privileged wrapper: `sudo sh -c "..."` through
  Run is not refused as a shell string, and the plugin that runs it is in
  review for the word on its own. The Sidecar `store-port` branch still
  carries Run 0.2.0 beside Store 0.2.0 (Store did not change); its next
  `omakit add store --update` moves it.
- Run does not fit a program that must live as long as the shell:
  Sidecar's daemon and its six `Process` sites stay bare.
- Store keeps one value of at most 64 KiB, does not lock, and refuses a
  base outside HOME; a cache a helper downloads is the helper's own
  transaction.
- `inspect` cannot see a Python daemon's writes, so the Sidecar port
  changes no count; the evidence there is the exercise.
- The resolver reads QML and same-file JavaScript; a path built in an
  included JavaScript module is unresolved, and the helper's rows stay
  counted. The closed-environment reading applies only when every QML
  site of a helper is a Run site.
- Sidecar 0.2.1 is broken on the shell of omarchy checkout `b5589fa`
  on `main` as on the port: its service reads `manifest.__sourceDir`,
  which that shell strips, so its guest lifecycle gives no evidence
  either way; whether the installed 4.0.3-1 shell strips it too was not
  tested.
- Every guest record before 2026-09-18 16:09 (`docs/evidence/blocks/*-lab-guest.json`,
  the two port records, the weigh lab records of 2026-09-14) was measured
  with the guest's session dev-linked to the omarchy checkout at
  `b5589fa` over the installed package, and did not know it. Each is
  annotated in place (`provenance`); the block suites were re-run on
  the unlinked guest (`docs/evidence/lab/`), the port acceptance and the
  weigh evidence were not.
- Theme Manager's memory file is not on Store yet.
- The lab's overlay is a named file removed by omakit, not a descriptor
  QEMU holds; a SIGKILL to omakit leaves QEMU on it until the next
  `prove` or `prune` finds it. The list of what the lab does not do, with
  the condition each needs, is the last section of `docs/LAB.md`.
- Base preparation depends on the omarchy-iso toolchain at a pinned
  commit with a packaged patch; omakit never fetches or patches it.
- One host, one day: the build and run times in M14 are one observation
  each.
