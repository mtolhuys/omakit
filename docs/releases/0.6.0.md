# 0.6.0

The plumbing plugin reviews block most, built and tested once. Two
blocks, tested files a plugin copies into its own tree with `omakit add`,
and `inspect` reading them; the README, the package description and the
tagline rewritten around that. Every number below is in the record it
names; nothing here says a plugin passes review, and no reviewer has
seen a ported plugin yet.

## What the review blocks on: M13

One reviewer's 1,001 security blocker comments over 6.7 days,
2026-09-10 to 2026-09-17, classified one by one. 587 raise something a
bounded process runner does, 527 something a private state file does,
and 777 of the 1,001 raise at least one of the two. That 777 is an
upper bound: it counts comments that raise the plumbing, not comments a
block would resolve. The record is
`docs/evidence/blocks/2026-09-17-review-blockers.json`; the comment
texts are not committed.

## Run 0.2.0, `omakit add run`

`blocks/run/`: `Run.qml` and `run-supervisor.py`, started through
`/usr/bin/python3 -I -S -B`. One program by absolute path, argv only
(string-program forms refused, best effort over the list in
`docs/BLOCKS.md`, unless `allowShellString` is on its own line), a
closed environment (`PATH=/usr/bin`, `HOME`, `LANG`,
`XDG_RUNTIME_DIR`, plus what `environment` names), a hard deadline,
byte and line caps while reading, control characters stripped, TERM
then KILL to the whole group through a pidfd, the leader reaped last,
one result object with a state word: `ok`, `exit`, `timeout`,
`overflow`, `cancelled`, `spawn-failed`, `supervisor-lost`,
`python-missing`. Chosen by the spike (`docs/BLOCKS_SPIKE.md`): 36 runs,
five scenarios, two designs, both end every scenario, the supervisor
chosen for reaping last. 0.2.0 is the hardening round of 2026-09-18
(`docs/evidence/blocks/2026-09-18-review.json`): the protocol between
`Run.qml` and the supervisor carries a per-run token the program cannot
see, so a line the program writes into the pipe through `/proc` changes
nothing; a supervisor that dies leaves no group behind; a program forked
before `Run.qml` knew its pid waits behind a gate; a `start()` queued
behind the backstop follows in order; and the string-program refusal
covers the forms `docs/BLOCKS.md` lists. The lab suite `tests/lab/run/`
holds 19 scenarios, six of them new and each failing on 0.1.0: 19 of 19
on the desktop and 19 of 19 on the stock 4.0.3 guest
(`docs/evidence/blocks/2026-09-18-run-lab-desktop.json`, `-guest.json`).
Each contract line in `docs/BLOCKS.md` carries its M13 count.

## Store 0.2.0, `omakit add store`

`blocks/store/`: `Store.qml` and `store-helper.py`, taken from Theme
Manager's cache transaction. One private file per plugin under the XDG
state or cache base, reached from `HOME` by descriptor with
`O_NOFOLLOW|O_DIRECTORY` at every step, checked after every open and
never before (owner, regular file or directory, not group- or
other-writable), read under a cap and a JSON schema subset, written
through an exclusive 0600 staging file and a rename with fsync, stale
staging swept after 600 s. States `ok`, `missing`, `invalid`,
`refused`, `overflow`, `failed`, `helper-failed`. `store` brings `run`,
which it starts its helper through. The lab suite `tests/lab/store/`
plants 12 hostile conditions in a throwaway HOME (links at the
directory, the parent and the file, a swap under the read, an oversized
file, a group-writable and a foreign-owned file, an invalid document, a
crash between staging and rename, ten concurrent writers, a base outside
HOME, and from 0.2.0 a FIFO at the file's name, a write cut short by
`RLIMIT_FSIZE`, a non-ASCII file within the cap): 15 of 15 on the
desktop and 15 of 15 on the stock guest, the foreign owner simulated
with sudo there (`docs/evidence/blocks/2026-09-18-store-lab-desktop.json`,
`-guest.json`). 0.2.0 opens the file without blocking and refuses a
FIFO by name, writes every byte or fails with nothing staged, carries
the value as UTF-8, counts the write cap in bytes and caps the schema,
closes the walk's descriptors on a refusal, and refuses a schema outside
the subset or a value nested past 64 levels without a traceback.
The helper is importable: `open_private_directory` and `result_of` take
the environment from the importer.

## Blocks as files

Six-line headers name the block, its version, the licence, the omakit
commit and the body's sha256; `blocks/history.json` is the append-only
record of every shipped body, and `omakit add <block> --update` moves an
unmodified copy to the current version and refuses a modified one.
`omakit add` is the one command that writes into a plugin tree, and it
writes only under `omakit/`. A `NOTICE` lists every block present.

## inspect reads the blocks

- An unmodified block is one `blocks` row and raises nothing at its
  lines; a modified copy is reported as modified and read like any other
  file.
- A `Run {` site is a process whose deadline the block holds
  (`deadline.via: "block-run"`); a `Store {` site is a write under the
  plugin's own directory at mode 0600 (`via: "block-store"`).
- A helper the QML starts through Run runs in the block's closed
  environment: its shell rows carry `closedEnvironment: true` and the
  environment-trust class counts their tool names apart. A helper is
  Run-started only when a site's `argv[0]` resolves to it through the
  text (literals, `+` chains, `Qt.resolvedUrl`, `Quickshell.env`,
  identifiers through the nearest assignment or binding, same-file
  functions through their return expressions); a path the text does not
  show resolves to nothing, and the row stays counted. Measured on Theme
  Manager: the superseded base-name rule read 481 to 298 with 183 names
  in 12 helpers; the resolved rule reads 484 to 434 with 50 names in 9
  helpers, 12 of 24 sites resolving.
- A line starting with `exec` is a process site; an argv word that is
  an expression is not a tool resolved from PATH.

## Limits

- No reviewer has seen a ported plugin. Both ports are branches; the
  submissions and their outcomes are still ahead, and the evaluation
  date in `docs/BLOCKS_PLAN.md` is 2026-10-15.
- M13's counts come from a classifier over review comments and are an
  upper bound on what a block can own; "raises" is not "resolves".
- The blocks need `/usr/bin/python3` on the machine; a stock Omarchy
  4.0.3 has it, and `Run.qml` reports `python-missing` otherwise.
- Run does not fit a program that must live as long as the shell:
  Sidecar's daemon and its six `Process` sites stay bare.
- Store keeps one value of at most 64 KiB, does not lock, and refuses a
  base outside HOME; a cache a helper downloads is the helper's own
  transaction.
- `inspect` cannot see a Python daemon's writes, so the Sidecar port
  changes no count; the evidence there is the exercise.
- The resolver reads QML and same-file JavaScript; a path built in an
  included JavaScript module is unresolved, and the helper's rows stay
  counted. The closed-environment reading applies only when every QML
  site of a helper is a Run site.
- Sidecar 0.2.1 is broken on stock 4.0.3 on `main` as on the port: its
  service reads `manifest.__sourceDir`, which that shell strips, so its
  guest lifecycle gives no evidence either way.
- Theme Manager's memory file is not on Store yet.
