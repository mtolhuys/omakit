Account-wide validation watch lets plugin authors check their open marketplace requests without collecting issue URLs.

- `omakit watch --all` discovers and checks every open marketplace issue authored by the account signed in through `gh`.
- `omakit watch` opens a numbered terminal picker with multiple selection, `all` and cancellation.
- `omakit watch --list` lists requests and commands for checking them individually.
- `--user <login>` selects a public account; `--json` and `--out` support automation without prompting.
- Batch reports show commit comparisons, validation findings and capabilities, issue labels, and the latest human discussion other than the author's. Independent read failures stay visible while other checks finish.
- Normal terminal use checks npm for a newer Omakit release at most once daily and shows the upgrade command when one is available. Scripts, JSON, offline runs and CI stay quiet; `DISABLE_UPDATE_NOTIFIER=1` disables the notice. Checks have a one-second network budget and failures retry after an hour.
- Semantic version comparisons distinguish newer releases from development installs and prereleases. `upgrade` never downgrades a version ahead of npm or installs an invalid registry target.

Each invocation is one snapshot. A current validated commit can still await review, approval or publication. Watch remains read-only and posts nothing.

The existing single-issue command remains available. No runtime dependencies were added. Validation included the full test suite on Node 22 and Node 24, a live check of five marketplace requests, and multiple selection in a real terminal.
